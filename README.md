# tiritara-privacy

tiritara.dev（tiritara）が公開するアプリのプライバシーポリシー。日本語・英語の静的HTMLを、GitHub Pagesで公開しています。

## 公開URL

- Android: https://kagen.github.io/tiritara-privacy/
- iOS・iPadOS共通: https://kagen.github.io/tiritara-privacy/ios.html
- iOS英語セクション: https://kagen.github.io/tiritara-privacy/ios.html#en

Androidの既存URLと本文は維持し、上部にiOSページへのリンクだけを追加しています。旧URL `kagen.github.io/kattalyst-privacy/` は既存アプリが掲載しているため、転送ページとして残してあります。

Androidページの `?app=アプリ名` は表示名だけを変更します。情報の取扱いを変更する機能ではありません。iOSページはアプリ名の差し替えに依存せず、共通方針とアプリ別の取扱情報を静的に掲載します。JavaScriptなしで全文を読めます。

## iOSアプリを追加するとき

同じ共通URLを複数のアプリで使用できます。ただし、新しいアプリの実態を未確認のまま掲載済みアプリの説明を流用しないでください。

1. 新しいアプリの実装、権限、SDK、通信先を確認します。
2. `ios.html` の日本語・英語の「アプリ別の取扱情報」に項目を追加します。
3. データの種類、目的、送信先、広告・分析・追跡、購入、アカウント、保存期間、削除方法を明記します。使わない機能も分かるようにします。
4. 新しい外部サービスがあれば、情報の取扱いとポリシーリンクを共通セクションにも追加します。
5. 実質的な変更がある場合は更新日を変更し、必要な利用者への通知・同意を準備します。
6. App Store ConnectのApp Privacy回答、プライバシーマニフェスト、権限の用途説明、アプリ内リンクと照合します。
7. 変更を公開し、ログイン不要でHTTP 200になることを確認してから、新しいアプリの公開・更新を行います。

共通ポリシーを作っても、App Storeのデータ収集申告がアプリ間で共通になるわけではありません。申告はアプリごとに行います。

## 六曜暦iOS版の提出前に再確認する事項

- Open-Meteoの現行ポリシーは、IPアドレスおよび座標を含み得るログの保持（90日）を説明しています。開発者自身が受信しないことだけを理由に「データ収集なし」としないでください。外部サービスの実際の取扱いに照らし、位置情報・診断等の申告要否と目的を確認してください。
- 現在のコードはOpen-Meteoの公開APIを使用しています。無料APIの非商用条件と有料機能を含むアプリでの利用条件について、提供元の許諾・契約を確認してください。このページの公開によって利用許諾が得られるわけではありません。
- プライバシーポリシーとWeatherKitの法的帰属リンクは別のものです。両方をアプリ内に保持してください。
- このポリシーは実装と公開資料に基づく説明です。法域ごとの適法性や審査通過を保証するものではなく、必要に応じて専門家へ確認してください。

## 公開方法

GitHub Pagesは `main` ブランチのルートから公開します。変更をコミットして `main` へプッシュすると反映されます。Androidの既存パスを削除・移動しないでください。
